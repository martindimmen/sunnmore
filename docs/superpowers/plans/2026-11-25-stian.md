# Stian Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Stian, the fourth friend: a happy, tipsy, smoking builder who builds a small church, block by block, from the materials players put in a Kyrkjetomt plot. A Bjørneunge in the plot makes him build faster and sloppier.

**Architecture:**
- **The church** is a drawing in a data file (`data/sunnmore/church/stian_kyrkje.json`: a legend plus one text grid per layer). The plain-Java `ChurchBlueprint` reads it and gives the build order and the materials list. `ChurchProgress` decides the next step. Both are unit tested.
- **The plot** is a block with a 27-slot container block entity, like vanilla's barrel. It is also Stian's lure (a point of interest).
- **Stian** is a `PathfinderMob` like Bård, with a building goal that walks to a plot and places blocks from its inventory.

**Tech Stack:** Minecraft 26.3, Fabric Loader 0.20.1, Fabric API 0.167.0+26.3, Java 25, JUnit 5, Gson (the plan parses JSON with Minecraft's own Gson).

**Spec:** `docs/stian-design.md`

## Global Constraints
- **Ids:**
  - Entity `sunnmore:stian`, egg `sunnmore:stian_spawn_egg`.
  - Items `sunnmore:bjorneunge` and `sunnmore:kyrkjetomt` (block item).
  - Block-entity type `sunnmore:kyrkjetomt`, POI `sunnmore:stian_lure`, projectile entity `sunnmore:thrown_bjorneunge`.
  - Visit attachment `sunnmore:stian_visits`, command `/stianvisit`.
  - Players see **Stian**, **Bjørneunge**, **Kyrkjetomt**.
- **Materials** (from the drawing; the test pins them): 172 birch planks, 40 birch logs, 12 birch stairs, 1 birch door, 51 cobblestone, 68 cobblestone stairs, 1 cobblestone wall, 15 glass panes, 1 lantern, 4 torches. That makes 366 placements.
- **Placing:** one block every 10 ticks. Each Bjørneunge gives 50 blocks at 5 ticks.
- **Mistakes:** only while boosted, 1 in 20, and only a rotation change (stairs facing or half, door hinge). Never a different block, never outside the footprint.
- **Never wreck anything:**
  - Only air and replaceable plants (`BlockTags.REPLACEABLE`, e.g. short grass, flowers, ferns, snow layers) may be replaced.
  - A placement takes exactly one item from the plot. If the block can't be placed, the item stays.
  - A Bjørneunge never drops from his can throw.
- **Timers:**
  - Hiccup every 400–800 ticks; trip every 2400–4800 ticks, sitting for 30 ticks.
  - Smoke puff every 60–120 ticks; røykepause every 1800–3600 ticks while building, lasting 80 ticks.
  - Can throw at most every 60 ticks.
- **Kill penalty:** as Bård's (40 health, no drops or XP, Slowness I and Weakness I for 6000 ticks, red broadcast `chat.sunnmore.stian.killed`).
- **Chat:** `<Stian>`. Lines are written with the `sunnmorsk` skill and are never another friend's signature lines.
- **Recipes:**
  - Bjørneunge: iron nugget + wheat + sugar.
  - Kyrkjetomt (my call, settled here): chest + birch sign + compass, shapeless.
- **Leave alone:** Glenn, Jinith and Bård are unchanged. Shared files only get additions.

## Review Focus
1. **Something in the way:** a plot placed against a hill, a tree or a player's chest must never break or replace anything. He refuses and the plot reports it → `clearanceBlocksSolid` (pure) and a manual check.
2. **Materials conservation:** every item taken from the plot becomes exactly one block. Placing (`setBlock`) can fail, and the plot can be broken mid-build → `ChurchProgressTest.takeOnlyWhenPlaceable`, and a manual "break the plot halfway" check.
3. **Blocks that need support** (torches, lantern, door) placed before their support would pop off and lose the item. They are flagged `"last": true` in the legend and built after everything else → `fragileBlocksComeLast`.
4. **Resuming:** after a restart or chunk unload, progress is read from the world (a position counts as done when it already holds the blueprint's block, whatever its rotation), so nothing is placed twice and mistakes aren't "fixed" → `doneMeansSameBlockAnyRotation`.
5. **Two Stians, or a plot near another plot:** each placement re-checks that its position is free and the item is in the plot, in the same tick. The plot search picks the nearest unfinished plot.

**Interfaces (produces):**
- **The JSON format:**
  - `{"legend": {"<char>": {"block": "<block state string>", "item": "<item id or null>", "last": <bool>}}, "layers": [[row strings, z 0..depth-1], ...]}`.
  - Layer index is y. In each row string, the character index is x.
  - `' '` and `'.'` mean nothing is placed there (the position is left as it is). They still count for the clearance check, as air.
  - The front (door) is at z=0, and blueprint "north" is the front.
- **`ChurchBlueprint`:**
  - `record Placement(int x, int y, int z, String block, @Nullable String item, boolean last)`
  - `static ChurchBlueprint parse(String json)`: uses Gson. Throws `IllegalArgumentException` on a symbol that isn't in the legend, or on rows of different lengths.
  - `int width()`, `int height()`, `int depth()`
  - `List<Placement> buildOrder()`: every non-blank cell; all `last=false` placements before all `last=true` ones. Within each group: y ascending, then z, then x.
  - `Map<String, Integer> materials()`: item id to count, skipping null items.
  - `static String blockId(String state)`: the id before `[`.
- **`ChurchProgress`:**
  - `sealed interface Step permits Place, Missing, Finished`, with `record Place(Placement p)`, `record Missing(String item, int stillNeeded)` and `record Finished()`.
  - `static Step next(List<Placement> order, Predicate<Placement> done, ToIntFunction<String> available)`:
    - Returns the first placement that isn't done.
    - If its item has 0 available, returns `Missing(item, number of not-done placements needing that item)` instead.
    - Placements with a null item (door upper half) are done together with their lower half by the world code, so `next` skips them.
  - `static Map<String, Integer> stillNeeded(List<Placement> order, Predicate<Placement> done)`
- **`StianMath`:**
  - Constants: `PLACE_TICKS=10`, `BOOSTED_PLACE_TICKS=5`, `BLOCKS_PER_CAN=50`, `MISTAKE_ONE_IN=20`, `CAN_COOLDOWN=60`, `NEVER=-CAN_COOLDOWN`, `PLOT_SEARCH=32`, and the timer ranges from Global Constraints.
  - Functions:
    - `boolean canThrow(long now, long last)`
    - `boolean isMistake(int roll)`: true when `roll == 0`, with roll in `[0, MISTAKE_ONE_IN)`
    - `int placeTicks(boolean boosted)`
    - `int between(int min, int max, int roll)`

### Task 3: Stian on the server (tipsy, smoking, can, chat, death, building)

  - `ThrownBjorneunge.java`: `extends ThrowableItemProjectile`, default item `BJORNEUNGE`.
    - `onHitEntity`: no damage. A knockback of 0.5 along the flight direction, with `hurtMarked`. A "klonk" sound (`SoundEvents.COPPER_HIT` or anything that fits). Then `discard()`.
    - `onHitBlock`: the sound, then `discard()`. Never drops the item.
  - `StianLines.java`: pools `ARRIVE(2)`, `LEAVE(2)`, `HIT(3)`, `HICCUP(2)`, `TRIP(2)`, `SMOKE_BREAK(2)`, `START(2)`, `MISSING(2)`, `BLOCKED(2)`, `BOOSTED(2)`, `FINISHED(2)`, `DEATH(1)`. A missing line takes the item name and count as `%s`.
  - `StianEntity.java`: `extends PathfinderMob implements VisitingFriend`.
    - **Synced flags:** `SITTING` (after a trip) and `SMOKING` (during a røykepause, a raised hand).
    - **Drift:** while moving, a small random sideways `setDeltaMovement` nudge.
    - **Timers** from `StianMath`.
    - **Particles:** smoke puffs are `ParticleTypes.SMOKE` at the mouth (server `sendParticles`; never fire); hiccups are `ParticleTypes.POOF` with a sound.
    - **Hit:** a `ServerPlayer` attacker gets a can thrown at them (`canThrow`), plus a `HIT` line. He never stops building.
    - **Death:** as Bård's.
    - **Visits:** as Bård's `maybeLeave`, but he doesn't leave while `isBuilding()` (the plot holds the next block's item).
  - `goal/BuildChurchGoal.java`: priority 2.
    1. Find the nearest `stian_lure` POI within `PLOT_SEARCH` whose church isn't finished, with `PoiManager.findAll`, sorted by distance.
    2. Walk to within 6 blocks of the next placement.
    3. If `obstacles()` isn't empty, say `BLOCKED` once and give up on that plot until it changes (re-check every 200 ticks).
    4. Every `placeTicks(boosted)`, ask `ChurchProgress.next`:
       - **`Place`:** take one item from the plot, `setBlock(pos, state, 3)`; if that returns false, put the item back. The door places both halves. When boosted and `isMistake`, rotate the stair or door state wrongly first. Each Bjørneunge taken from the plot sets `boostedBlocksLeft += 50`.
       - **`Missing`:** say it once per item, then idle.
       - **`Finished`:** say `FINISHED`, then stop.
    5. A røykepause interrupts the placing for 80 ticks.
