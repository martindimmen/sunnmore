# Bård Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Bård, the third friend. He forecasts the real weather, sells one weather change per in-game day for diamonds, strikes harmless lightning next to anyone who hits him, and visits like the others, with a Værstasjon lure.

**Architecture:**
- **Pure rules:** the weather rules are plain Java, free of Minecraft classes, and unit tested: `WeatherForecast` (what the countdowns mean), `WeatherShopMath` (what a purchase writes, and when the deals are open) and `BardMath` (timers).
- **The entity:** `BardEntity` is a `PathfinderMob` like Jinith, and implements `Merchant` like Glenn. `BardWeather` owns the world-wide "day of the last change" attachment and applies purchases to the server's `WeatherData`.
- **Client:** a humanoid model with a butt part and a phone.
- **Visits:** visits and the lure plug into the existing `FriendVisits` and `LureBlocks`.

**Tech Stack:** Minecraft 26.3, Fabric Loader 0.20.1, Fabric API 0.167.0+26.3 (object builder, data attachment, command, lifecycle, creative tab events), Java 25, JUnit 5.

**Spec:** `docs/bard-design.md`

## Global Constraints
- **Ids:** `bard` in all ids, classes and keys; players see **Bård**.
  - Entity `sunnmore:bard`, egg `sunnmore:bard_spawn_egg`, item `sunnmore:vaermelding`, block `sunnmore:vaerstasjon`, POI `sunnmore:bard_lure`.
  - Visit attachment `sunnmore:bard_visits`, weather-day attachment `sunnmore:bard_weather_day`, command `/bardvisit` (op).
- **Prices:** Sol 1 diamond, Regn 1 diamond, Torden 5 diamonds.
- **Daily limit:** one change per in-game day, world-wide, shared by all Bårds. The day is `GlennTrades.currentDay(overworld)`.
- **Deals closed:** when `doWeatherCycle` (`GameRules.ADVANCE_WEATHER`) is off, or Bård is not in the Overworld.
- **Purchases:**
  - A purchase never shortens the weather it buys.
  - Sol never uses the forced-clear timer, and never goes through `MinecraftServer.setWeatherParameters`. Write the `WeatherData` countdowns directly.
- **Lightning:**
  - Visual only (`setVisualOnly(true)`), 1 to 2 blocks from the player, at most once per 60 ticks per Bård.
  - It never lands on a block that is copper, waxed copper or a lightning rod: a visual bolt still de-ages copper and powers rods.
- **Health and killing:** 40 health, no drops, no XP. The killer gets Slowness I and Weakness I for 6000 ticks, plus a red broadcast `chat.sunnmore.bard.killed`.
- **Chat:**
  - `<Bård>` prefix. Lines reach 16 blocks; the arrival line reaches 64.
  - Lines are in Sunnmørsk via the `sunnmorsk` skill, under `chat.sunnmore.bard.*` in `en_us.json`.
- **Leave alone:** Glenn's and Jinith's code and behaviour stay unchanged. Bård copies what he needs from them instead of refactoring them.

## Review Focus
1. **Two buyers at once** (two players at one Bård's screen, or at two Bårds): the second must not lose diamonds without getting a weather change. Every open Bård screen is closed out in the same server tick as the purchase → Task 3, the `closeShopsToday` refresh plus a manual two-screen check.
2. **The bolt on a build:** a hit next to a copper roof or a lightning rod must not change any block or power any redstone → the spot filter in Task 2, plus a manual check next to a lightning rod.
3. **Countdowns at 0** (the tick right after a change): the forecast must say nothing wrong → `zeroRainCountdownIsUnsettled`, `stormWithZeroThunderIsUnsettled`.
4. **New day with the screen open:** the deals stay as they were until the screen is reopened, then they reopen → `dealsOpenOncePerDay` (pure), plus a manual `/time add 24000` check.
5. **A visit ends mid-trade:** he never leaves while someone has his screen open → the `maybeLeave` guard in Task 2.

**`WeatherForecast.of`**
The tests don't fully determine it; this mirrors `ServerLevel.advanceWeatherCycle`. In that method, thunder is processed before rain in the same tick, and a countdown that has just reached 0 is redrawn on the next tick.
- **Forced clear** (`clearTime > 0`): `STORM` in `clearTime + 1`. Vanilla flips both flags on just after it ends.
- **Raining:**
  - If `rainTime == 0` or `thunderTime == 0`, the forecast is unsettled.
  - **Thundering:**
    - If `thunderTime < rainTime`, the next weather is `RAIN` in `thunderTime`.
    - Otherwise it is `CLEAR` in `rainTime`.
  - **Not thundering:**
    - If `thunderTime < rainTime`, the next weather is `STORM` in `thunderTime`.
    - Otherwise it is `CLEAR` in `rainTime`.
- **Dry:**
  - If `rainTime == 0`, the forecast is unsettled.
  - Otherwise rain starts in `rainTime`. It is `STORM` only if the thunder flag is certainly on at that tick. Work out the flag at rain start like this:
    - `thunderTime > rainTime`: `thundering`, certain.
    - `thunderTime == rainTime`: `!thundering`, certain.
    - Otherwise:
      - `f` is `thundering` if `thunderTime == 0`, else `!thundering`.
      - `t0` is `thunderTime`.
      - The next flip comes at the earliest at `t0 + 1 + (f ? THUNDER_DURATION_MIN : THUNDER_DELAY_MIN)`.
      - The flag is certainly `f` when `rainTime` is less than that.
  - If the flag is uncertain, the forecast is `RAIN`: the rain itself is certain.

**`phrase`:**
- `ticks < 1200` → `SOON`.
- Otherwise `m = ceil(ticks / 1200)`:
  - `m < 60` → `MINUTES m`.
  - Else `HOURS max(1, round(ticks / 72000.0))`.

**`purchase`:**
- **SOL:**
  - Result: `clear = 0`, `raining = false`, `thundering = false`, `thunderTime = thunderDelay`.
  - `rainTime = max(left, rainDelay)`. `left` is how long the dry weather has left: `clearTime` if `clearTime > 0`, else `rainTime` if it is dry now, else 0.
- **REGN:**
  - Result: `clear = 0`, `raining = true`, `thundering = false`.
  - `rainTime = max(left, rainDuration)`. `left` is `rainTime` if it is RAIN now (not STORM), else 0.
  - `thunderTime = max(thunderDelay, rainTime + 1)`, so no storm starts inside the rain you bought.
- **TORDEN:**
  - Result: `clear = 0`, `raining = true`, `thundering = true`.
  - `rainTime = thunderTime = max(left, thunderDuration)`. `left` is `min(rainTime, thunderTime)` if it is STORM now, else 0.
