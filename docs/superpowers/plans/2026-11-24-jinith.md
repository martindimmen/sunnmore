# Jinith Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Jinith: a buff, friendly medic NPC who heals players near him. If you punch him he turns red and beats you to exactly half a heart, then patches you up.

**Architecture:**
- **Server:** `JinithEntity extends PathfinderMob` (not Monster: no peaceful despawn, no sleep blocking, golems leave him alone). His anger is a field holding the attacker's UUID, and a synced boolean drives the red skin. His punch is a data-driven damage type tagged to skip armor, shields and enchantments. The damage is capped by plain-Java math. A Fabric `ALLOW_DEATH` hook makes the 3-second safety window.
- **Client:** his own `HumanoidModel` geometry, using the vanilla part names, so walking and the attack swing animate for free. A `HumanoidMobRenderer` swaps between the normal and the red texture.

**Tech Stack:**
- Minecraft 26.3, Fabric Loader 0.20.1, Fabric API 0.167.0+26.3, Java 25, JUnit 5.
- Pillow for the textures. The script goes in the scratchpad; only the PNGs are committed.

**Spec:** `docs/jinith-design.md`

## Global Constraints
- **Package and id:** package `martidi.sunnmore.jinith` (client: `martidi.sunnmore.client.jinith`); entity id `sunnmore:jinith`.
- **Unchanged:** Glenn's code and behaviour. Reach the Sunnmøre tab through `CreativeModeTabEvents.modifyOutputEvent(GlennItems.SUNNMORE_TAB_KEY)`.
- **Chat:** lines show as `<Jinith>` and are written in Sunnmørsk (ej, e, igjen, morga, he). Keys are `chat.sunnmore.jinith.<pool>.<n>` in `assets/sunnmore/lang/en_us.json`.
- **Numbers:**
  - 100 max health; 8 attack damage (4 hearts); knockback resistance 0.8; follow range 32.
  - Heal radius 6, with Regeneration I for 100 ticks. The patch-up gives Regeneration II for 200 ticks.
  - The safety window is 60 ticks; he gives up after 32 blocks or 1200 ticks without a hit.
- **Never kill:** his punch never takes a player below 1.0 health. Within the safety window, no damage source except the `minecraft:bypasses_invulnerability` types (void, /kill) can kill a protected player.

## Review Focus
1. **Absorption:** a player with absorption hearts (golden apple) should still end at exactly 1.0 health, never 0. The damage cap counts absorption → `JinithMathTest.capCountsAbsorption`.
2. **Resistance or Protection:** a player with the Resistance effect or Protection armor should end above 1.0 health, not dead and not stuck. The tags skip enchantments, Resistance can lower the damage, and the cap only ever lowers it → `capNeverRaisesDamage`.
3. **Already at half a heart:** if the target is already at 1.0 health or less when he swings, he deals no damage and goes straight to the patch-up → `capIsZeroAtHalfHeart`.
4. **Creative or Peaceful attacker:** a punch from a Creative player, or any punch in Peaceful, turns him red briefly, then he calms down quietly within 60 ticks. He never hunts forever → `giveUpWhenUnattackable`.
5. **Regeneration renewal:** while you stand next to him the heal must keep ticking. Renew only when the effect is missing or has under 20 ticks left, so the heal timer is not reset every check → `renewRegenOnlyNearEnd`.

### Task 1: Pure logic (`JinithMath`)

**Files:**
- Create: `src/main/java/martidi/sunnmore/jinith/JinithMath.java`
- Test: `src/test/java/martidi/sunnmore/jinith/JinithMathTest.java`

**Interfaces:** produces these signatures:
- `static float cappedDamage(float base, float health, float absorption)`
- `static boolean shouldPatchUp(float healthAfter)`
- `static boolean shouldGiveUp(long now, long lastProgressTick, double distanceSqr, boolean sameLevel, boolean attackable)`
- `static boolean needsRegenRenewal(boolean hasRegen, int remainingTicks)`
- `static boolean isProtected(long now, long protectedUntil)`
- Constants: `HALF_HEART = 1.0F`, `GIVE_UP_DISTANCE = 32.0`, `GIVE_UP_TICKS = 1200`, `UNATTACKABLE_GIVE_UP_TICKS = 60`, `SAFETY_TICKS = 60`, `REGEN_RENEW_BELOW = 20`

- [ ] **Step 1: Write the failing tests**
  - `capKeepsHalfHeart`: `cappedDamage(8, 20, 0) == 8`; `cappedDamage(8, 5, 0) == 4`; `cappedDamage(8, 1.5f, 0) == 0.5f`
  - `capCountsAbsorption`: `cappedDamage(8, 5, 4) == 8`; `cappedDamage(20, 5, 4) == 8`
  - `capIsZeroAtHalfHeart`: `cappedDamage(8, 1, 0) == 0`; `cappedDamage(8, 0.5f, 0) == 0`
  - `capNeverRaisesDamage`: for base in {0.5, 2, 8} and health in {1.5, 10, 20}, `cappedDamage <= base`
  - `patchUpAtHalfHeart`: `shouldPatchUp(1.0f)` and `shouldPatchUp(0.7f)` are true; `shouldPatchUp(1.5f)` is false
  - `giveUp`:
    - true when `!sameLevel`
    - true when `distanceSqr > 32*32`
    - true when `now - last > 1200`
    - false when all are inside the limits
  - `giveUpWhenUnattackable`: with `attackable = false`, true when `now - last > 60` and false at 59
  - `renewRegenOnlyNearEnd`: `needsRegenRenewal(false, 0)` is true; `(true, 19)` is true; `(true, 20)` is false; `(true, 80)` is false
  - `protectedWindow`: `isProtected(100, 160)` is true; `isProtected(160, 160)` is false

- [ ] **Step 3: Implement `JinithMath`.** The cap is `max(0, min(base, health + absorption - HALF_HEART))`.

### Task 3: The fight (anger, capped punch, knockback, safety, patch-up)

**Files:**
- Modify: `jinith/JinithEntity.java`
- Create: `jinith/JinithSafety.java`
  - a non-persistent attachment `sunnmore:jinith_safe_until` (Long) on the player
  - `static void protect(ServerPlayer p)`, which sets `now + SAFETY_TICKS`
  - `register()`, which adds a `ServerLivingEntityEvents.ALLOW_DEATH` handler: if a `ServerPlayer` is protected and `!source.is(DamageTypeTags.BYPASSES_INVULNERABILITY)`, call `setHealth(1.0F)` and return false

**Interfaces:**
- **Consumes:**
  - from Task 1: `JinithMath.*`
  - from Task 2: `JinithDamage.PUNCH`, `DATA_ANGRY`
  - from Task 4: `JinithLines.say(JinithEntity, Pool, @Nullable Entity about, boolean force)`, for the lines `angry`, `hit`, `patched_up` and `calm`. Implement Task 4's `JinithLines` first, or stub it.
- **Produces:**
  - `void becomeAngryAt(ServerPlayer p)`
  - `void calmDown(boolean patchUp)`
  - `@Nullable ServerPlayer angryTarget()`

- [ ] **Step 1: Becoming angry.** Override `hurtServer`. If `source.getEntity()` is a `ServerPlayer`, call `becomeAngryAt` with that player; a newer attacker replaces the old target. `becomeAngryAt` does this:
  1. stores the UUID
  2. sets `lastProgressTick = now`
  3. sets `DATA_ANGRY` to true
  4. calls `setTarget(player)`
  5. says the `angry` line (forced)
- [ ] **Step 2: Punching.** Override `doHurtTarget(ServerLevel, Entity)`:
  1. Only the angry target can be hit; anything else returns false.
  2. Compute `dmg = cappedDamage(attackDamage, health, absorption)`. If `dmg <= 0`, call `calmDown(true)` and return false.
  3. Hit with `level.damageSources().source(JinithDamage.PUNCH, this)`.
  4. On a hit:
     - call `causeExtraKnockback(target, getKnockback(target, src), oldMovement, src, dmg, true)`, and add upward speed so the player leaves the ground: `+0.35 y`, then `hurtMarked = true`
     - call `JinithSafety.protect`, `swing(MAIN_HAND)`, `setLastHurtMob`
     - play `PLAYER_ATTACK_STRONG`
     - set `lastProgressTick = now`
     - say a `hit` line (not forced)
  5. If `shouldPatchUp(target.getHealth())`, call `calmDown(true)`.
- [ ] **Step 3: `calmDown(boolean patchUp)`.**
  - Always: clear the UUID and the target, set `DATA_ANGRY` to false, and stop navigation.
  - If `patchUp`:
    - add Regeneration II (amplifier 1) for 200 ticks
    - show `HEART` particles at the player
    - call `JinithSafety.protect`
    - say the `patched_up` line (forced)
  - Else say the `calm` line (not forced).
- [ ] **Step 4: Giving up.** In `customServerAiStep`, check while angry. Find the target with `level.getPlayerByUUID`. If it is missing, or `shouldGiveUp(...)` with `attackable = !creative && !spectator && difficulty != PEACEFUL` returns true, call `calmDown(false)`.
- [ ] **Step 5:** Run `./gradlew build` and expect success.
